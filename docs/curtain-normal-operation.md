# dc1545 正常使用与旧状态迁移

本轮按用户最新要求取消卷帘专属启用、验证解锁和人工恢复流程。适用型号仍为 `dooya.motor.dc1545`，当前驱动核对 v1 URN 和固件 `1.1.3`；不扩大到其他型号。正常 App 没有卷帘调试模式或逐台启用开关。已配置且受支持的卷帘直接参与同一个设备轮询循环，并提供位置、全开、全关、停止。初始化本身不发控制命令。

## 电机反向退出 App 功能

SIID 2 / PIID 5 不再作为该型号的产品能力：能力目录、注入/缓存生成的设备快照、通用属性展示及编辑都排除它，引用它的 action 参数也不开放。通用 API 不另起卷帘查询，正常读写统一交给已有串行驱动，桥接 GET 继续读缓存。其他型号的 PIID 5 不受影响。反向查看/设置请使用手机米家。

初次、手动刷新、周期完整检查、控制前检查和旧验证 SDK 路径都使用 `[2.2,2.3,2.4,2.9,2.10]`。普通 adaptive 轮次继续读状态/位置 `[2.2,2.3]`，最多十次精简读取或距完整检查满 300 秒后重新完整检查。无六项自动回退。实际地址及 `normal-five` 标记保留在日志/测试 manifest 中。五项的返回码、类型、范围、fault=0、身份和时钟校验不放宽。

显式 CLI `curtain-attributes --properties 2.5` 或 `curtain-experiment --diagnostic-six` 仍可用于独立只读排因；计划必须明确选择，遇错即停，不影响 App 正常路径。历史 full6 证据不改名为 full5。

## 错误与交互

失败立即结束当前操作，清除不可信的当前位置，保留最近有效位置和时间并标注过期，显示原因且记录日志。正常 App 在统一轮询内复用普通设备的 `ProbeRetryPolicy` 退避：20、40、80 秒逐次增长，上限一天；只在退避截止后的下一轮检查，没有第二条计时器或积压请求。成功后清除错误和退避。恢复检查必须完整读取五项，不能仅凭位置/状态绕过 fault 或其他安全字段。只读隔离 App 实验仍在第一次错误时结束整个实验，不会跟随生产重试。

过去的失败不再成为永久控制门槛。新用户操作会重新校验身份/完整状态，写入仍单次、不自动重发，实际位置及电机停止状态用于有限回读确认；目标回显不作为成功。滑块松手期间已有读取在途时，目标只接收一次并等待；若该在途读取失败，这次等待目标明确显示未发送，不自动延后重发。用户可以在检查错误后再次明确操作，无需先解锁或手动恢复。Stop 原有优先级保留。

普通刷新保持静默：不切换阶段/忙状态，不禁用正在拖动的滑块，不覆盖拖动草稿或未提交文字。

## 迁移

| 原保存内容 | 升级行为 |
| --- | --- |
| `curtain.daily.enabled`，包括空名单或 false | 删除旧键，不作为控制/读取门槛 |
| `curtain.polling.paused`，包括历史 propertyError | 删除旧键；启动后的正常轮询重新检查，真实错误仍可见并退避 |
| 其他配置、token、配对、日志 | 保持原存储，不清空、不重置 |
| 未保存或非法的轮询间隔 | 前台 **5 秒**、后台 **30 秒** |
| 已保存的合法间隔，包括 5、10、自定义值 | 原样保留；旧版没有来源标记，不能将保存的 10 秒猜成旧默认后覆盖 |

因此已有设置为 10 秒的用户若要用 5 秒，需在正常设置页修改一次。这是全局间隔设置，不是卷帘启用门槛。目标是两轮开始之间的间隔，慢设备/初始化及同设备限频可拉长实际值；不重叠或补发。DEBUG 只读隔离测试的 configure 和 plan 从同一默认结构取得 5/30，后台隐藏生命周期不变。

## 验证与边界

本轮云端不向家庭设备发包。可先在 Mac 编译和离线验证：

```sh
swift build --product mijia-lan --force-resolved-versions
swift build --product MijiaLANApp --force-resolved-versions
swift test --filter 'DevicePollingTests|CurtainControlPreferenceTests|CurtainInteractionTests|CurtainNormalProfileTests|DeviceLANPolicyTests|DeviceLANPolicyNetworkTests|ReadOnlyAppTestTests|MatterSnapshotPollingTests' --force-resolved-versions
```

验收重点为：旧关闭/暂停偏好迁移后自动读取；无开关即可控制；正常路径不读写2.5；坏五项仍拒绝写入、失败后退避并自动检查；等待中读取失败不会悄悄发送旧目标；滑条/文字草稿保持；manifest 和设置均为新默认5/30且旧自定义值保留；只读实验仍无写入且遇错结束。

云端隔离 Swift **149项通过**；manifest改为共用默认值后，入口定向 **6/6通过**。全部 **122个Swift文件语法检查通过**。隔离包使用实际驱动、调度和BSD loopback，Linux报文编解码仍为替身；这些不替代原生macOS编译、AES/MD5进程回环、手势或实机长测。桥接缓存回归包含在隔离测试内，本轮没有改变Node桥接实现。

现场最强证据是客厅仅反复读取2.5时，本机该地址累计第38次请求首次-4004；书房不反复读取5时9/10累计各100次仍正常。计数只限已审计的 Mac 窗口，不代表所有设备固定38次上限，也未证明固件内存泄漏。详细最终329包、16阶段及原生48d验证边界见[现场兼容记录](curtain-five-property-compatibility.md)。本轮新版 App 的实机持续读取结果尚未产生，不把这些历史探针当作本轮通过。
