**当前候选以[卷帘通信策略与对照入口](curtain-communication-experiments.md)及[统一轮询说明](device-polling-and-log-history.md)为准：恢复按台日常控制开关，开启后使用修订策略轮询，既有失败暂停保留。本轮先做原生编译、离线与 loopback；下方较早阶段的行为和验收步骤保留为历史记录，不能视为新版本实机通过。**

本轮在 `f34c94e` 的保护逻辑上增加 App 内日常控制。适用于 `dooya.motor.dc1545`、固件 `1.1.3`、URN `urn:miot-spec-v2:device:motor-controller:0000A01D:dooya-dc1545:1`。设备详情可保存每台的启用选择；允许 0–100% 任意目标、全开、全关和运动中停止。原先“单次最多 5 个百分点”“每次重启重新启用”的限制不适用于日常入口。

**验收状态：六台 +5 位置探针是此前已有实机证据；本提交的 App 共存、任意位置、全行程和停止尚待家庭 Mac 验收。** 新增的全行程/停止回归使用人工构造设备，不补记为现场报文或硬件成功。旧故障原因仍未确定。既有现场摘要和风险样本完整保留，见[历史小幅验证](curtain-position-validation.md)及[现场记录](household-followup-diagnostics.md)。HomeKit/Matter 卷帘控制不在本轮开放。

## 规格、方向和实际请求

2026-11-07 再次核对[本型号公开规格页](https://home.miot-spec.com/spec/dooya.motor.dc1545)，与仓库 `Fixtures/dooya.motor.dc1545.json` 的 v1 投影一致。该页是公开规格展示，不是此固件的实机动作验收。页面写明位置 0 全遮住、100 全拉开；motor-control 的值 1 标为“暂停”，App 使用“停止”作为用户入口。回读 status 的 1 是停止。没有套用其他杜亚型号的命令。

所有写入均为 `set_properties`，每次数组只有一项、DID 使用配置 DID：

| App 入口 | SIID | PIID | value | 完成判定 |
| --- | ---: | ---: | --- | --- |
| 滑块松手 / 输入整数后点击“确认位置” | 2 | 4 | 0…100 整数 | 当前 2.3 等于目标，且 2.2=1 |
| 全开 | 2 | 1 | 2 | 当前 2.3=100，且 2.2=1 |
| 全关 | 2 | 1 | 0 | 当前 2.3=0，且 2.2=1 |
| 停止 | 2 | 1 | 1 | 读取有效的实际 2.3 位置，且 2.2=1；停止不要求到达旧目标 |

拖动和文字编辑只更新 UI 草稿，没有写入；滑块一次松手提交一次，文字需点击确认。相同进行中命令合并，刚确认后 2 秒内的同一命令去重，不追加写入队列；超过去重窗口再次明确操作会先新读状态，避免外部移动后仍一直忽略同一目标。目标范围和方向不因 `motor-reverse` 自动翻转，也不会自动设置反向。方向若与实物不符，该轮不通过，不能自动改写反向来“修复”。

读取使用 `get_properties`：启动、手动更新及普通后台读取的白名单为 `2.2/2.3/2.4/2.5/2.9/2.10`；运动确认只读 `2.3/2.2`。`2.1` 是只写属性，不读取。写前要求六项完整、地址唯一、code=0、类型/范围匹配、fault=0，且 motor status=1。位置、目标和状态分别保留，不用目标回显充当实际位置。

没有开放 `2.1=3/4` 向上/向下微调、`2.5` 电机反向或 `2.10` 模式写入；这些不属于本轮日常入口。没有旧 miIO 命令回退、额外 action、自动重新配网或升级。

## 调度与异常处理

- 每台共享一个客户端与串行事务。六台日常会话共用一个发包调度器，最多一个 UDP exchange 在途。普通包之间另留 250 毫秒全局间隔，避免同一轮六台同时发包；同设备普通包保留上次响应后至少 5 秒的间隔。**5 秒是当前保守节奏，来自小幅探针对照，不是协议硬要求。**
- 一个 App 后台循环每轮先等 30 秒，再按设备逐台读取；没有每台独立定时器。前台操作进行中跳过该设备；异常/未确认状态不发自动读取。启用或重启只读身份与状态，绝不恢复发送上次目标。
- 写入只发一次。有效“运动中”状态会继续回读实际位置，每次间隔至少 5 秒；普通运动确认最多 24 次且 120 秒期限先到为准。停止确认最多 6 次且 30 秒期限先到为准。到期不补写、不改变目标。排队等待或操作系统网络延迟可能推迟任务返回；发送层也检查期限，过期不再发该次确认读取。
- 写入丢失应答时显示未确认，立即退出自动确认流程；不重发，不假定设备未动作。用户可点“仅回读确认”，它只读、不会重发任何写入。实际完成可以被确认，但丢失的写入应答不会补记为收到。仍不确定时可结束本轮并重新连接，只恢复读取。
- 缺值、错误返回码、响应 ID/设备头不匹配、类型冲突、旧错位回包都会暂停该设备的后台读取并清除当前可信读数。只有显式回读、重新连接或用户发送停止会追加请求，不自动重试。失败保留每台启用偏好；关闭控制或退出不会发送物理停止。
- 用户选择保存在 App UserDefaults 的 `curtain.daily.enabled`，只有设备 ID，不包含 token。设备连接身份/规格改变会使旧会话失效；新会话仍检查配置 DID 与握手 DID、加密响应、型号、固件。未选设备的通用属性路径仍受保护。

### 停止如何优先

停止入口独立于普通 `isWorking` 限制，运动中、等待回读或普通读取时均可使用。点击后取消该设备等待中的普通写入/回读，丢弃旧事务后续动作；已经发出的目标不会被“撤销”，随后需要发出真正的 `2.1=1`。

停止跳过同设备 5 秒等待和全局 250 毫秒间隔，排在所有已排队普通流量前。已经在途的单个 UDP exchange 必须结束，当前验证通道每包超时 2 秒；不能撤回已发送 UDP。若客户端时钟失效，只在同一优先许可中执行必要的 hello、核对 DID，再立即发一次停止，期间不插入 info、完整属性批次或其他设备普通请求。重复点击停止由 UI 合并；停止写入自身也没有自动重试。

2 秒是传输等待配置，不是端到端停止响应保证；网络、ARP、系统调度及已有在途请求均可能增加耗时。停止应答后仍按有间隔、有上限的只读方式确认实际停止。按钮可点击、写入应答和电机实际停下是三个不同验收点；这不是已通过实机验证的紧急停止保证。

### 避免旧路径叠加

日常控制启动前等待正在进行的发现/手动添加探测结束，取消并排空所有卷帘的旧 info 探测。这个 App 进程余下时间不再广播发现或启动旧卷帘探测。普通“重试”对已选卷帘改走独立会话重新连接；手动添加设备暂缓，避免另起客户端碰到现有卷帘。

此阶段的限制：若需探测新设备或通过广播更新 DHCP 地址，先关闭全部卷帘的日常控制并重启，再使用原有发现/添加入口；之后可重新按台启用。用户的配对和凭据不重置。其他型号原有轮询/控制保持可用。

App Matter snapshot 继续只读共享缓存；独立 CLI Matter 只轮询可导出的设备。通用能力、CLI 原始属性入口、HomeKit/Matter 映射对该型号继续关闭。日常会话结果只供 App 使用，不把卷帘伪装为其他设备或偷偷开放桥接。

### 阶段二：家庭环境只选一台

先由用户指定一台容易观察、运动路径可见的卷帘。不要先批量开启六台。确认运行的是本次构建产物，记录进程路径、可执行文件 SHA-256、源码 SHA；HomeKit/Matter 关闭，不扫码、不重置配对。此后每轮等本轮请求结束再检查手机米家控制，不并发运行外部探针或另一个旧 App。

| 顺序 | 操作与通过条件 |
| --- | --- |
| 1. 初始与重启 | 只开启这一台；检查实际位置与米家/实物一致。正常退出再打开，选择保留，仅读取，不发生自动移动；记录 App 共存状态。 |
| 2. 中间位置 | 选 1–99% 内一个清晰的中间值。拖动时不动作，松手一次后实际运动；最终 2.3 到目标、2.2 停止。确认手机米家仍能驱动。 |
| 3. 大幅调整 | 选与当前位置相差明显超过 5 个百分点的目标。首次读到“运动中”应继续等待，不报失败、不重写目标。最终实际位置与停止状态匹配，实物一致；确认手机米家仍可控制。 |
| 4. 全开 | 点击全开，核对方向与实物完全打开、实际位置 100、状态停止；确认手机米家仍可控制。 |
| 5. 全关 | 点击全关，核对方向与实物全遮住、实际位置 0、状态停止；确认手机米家仍可控制。 |
| 6. 运动中停止 | 发起可观察的长行程，运动中立即点击停止。记录点击、停止应答、实物停止和最终位置/停止状态各自时间。不得等待旧目标到达才停止，也不得停止后又自动继续原目标；确认手机米家仍可控制。 |
| 7. 回读等待期间停止 | 在一次运动的回读等待期间点停止，验证不会被 5 秒普通等待或重复点击排队拖延。记录实物响应与 UI 应答/确认的区别；确认手机米家仍可控制。 |
| 8. 稳定运行 | 保持这台开启，观察低频后台状态更新及常规 App 导航，确认无自动移动/重复写入、没有另开全设备或旧卷帘探测；之后再以手机完成一次控制并等待 App 背景读取反映。持续时长由本地报告明确写出，不能外推全天稳定。 |

每轮至少记录：设备房间/标签（不带凭据）、开始实际位置、入口和目标、应答/未确认提示、最终实际位置与状态、物理动作、手机米家能否继续控制。不要反馈 token、完整配置、配对密钥或其他桌面截图。只读确认不会变成重发目标；如实际发生超时，按 UI 的未确认结果报告，不为“测超时”断网或重复写入。

方向错误、手机失控、意外动作、停止迟到、位置/状态不一致或回包异常时，该阶段不通过：停止自动后续操作，保存观察并退出；不重置、升级、猜测反向映射或继续批量测试。确需停止运动时由用户使用停止入口或既有实体遥控器。
