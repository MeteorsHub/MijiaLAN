# 安全修复与验证范围

本次修复基于 `262a540` 的源码审查；不表示产品已经完成独立安全认证或实机验收。

## HomeKit 输入与资源限制

在处理配对或鉴权前验证 HTTP 边界，拒绝负数、溢出、重复 Content-Length、分块编码以及超限报文。
限制为 8 KiB 请求头、56 KiB 请求体、每连接 128 KiB 接收缓冲；解密后尚未完成的请求最多 64 KiB。
Mac 服务端最多接收 32 个连接；未鉴权连接最多保留约 30 秒，半包最多约 15 秒，按 5 秒周期清理。
读取使用背压，每连接只处理一个入站任务，避免客户端绕过缓冲区限制堆积任务。
超过 1024 字节的加密帧、解密失败和非法 HTTP 请求会关闭连接。

这些是资源上限和输入校验，不是完整的网络抗拒绝服务保证。真实网络行为仍需家庭测试环境验证。

## HomeKit 配对权限与迁移

首次 Pair Setup 建立管理员。后续添加控制器时保存其权限，普通控制器可以操作设备，
但不能添加、删除或列出配对。拒绝在同一个控制器 ID 下替换公钥。
移除或降级最后一个管理员时撤销剩余用户，已撤销会话不能继续操作。
钥匙串写入失败不会更新内存中的角色；持久化操作串行执行。

旧版本配对格式只有公钥，没有权限，且所有控制器的实际行为均为管理员。
升级保留这份既有信任并在后续写入时持久化权限，不删除现有配对、不重新生成桥身份。
**无法从旧文件恢复从未记录的历史权限。** 如需限制某个旧控制器，应通过家庭平台移除后按所需权限重新添加；
不会在升级时擅自执行这一操作。

## 临时模拟配置

`MIJIALAN_UI_PREVIEW=1` 或 `MIJIALAN_EPHEMERAL=1` 使用每实例独立的临时 Matter 配对目录。
即使在该模式下手动打开 Matter，也不会读取正式 `Application Support/MijiaLAN/Matter` 配对数据。
正常退出会尽力清理临时目录；异常终止可能留下仅当前用户可读的临时文件。
隔离存储并不禁止临时模拟实例主动开启网络服务；工作电脑验证仍须保持两种桥接关闭。

## 米家登录与导入

App 的二维码登录、长轮询、serviceToken 交换和设备清单导入统一使用 `XiaomiHTTPTransport`。
初始请求和每次重定向只允许 HTTPS、标准 HTTPS 端口、无 URL 用户名或密码，
目标限定为 `account.xiaomi.com` 及其子域名，以及明确列举的 Xiaomi Home API 区域和 STS 主机。
二维码中的登录地址在显示前校验；拒绝跳转到开发者域名、仿冒域名或降级到 HTTP。
继续使用系统 TLS 证书校验和临时 URLSession，不共享或持久化 cookies；错误不回显登录 URL。

这不会把社区实现变为小米官方 App，也不会把获取的米家会话自动变成只读授权。
它不抵御被攻陷的系统信任根、同账号恶意进程或受控的小米官方服务。
设备规格下载不携带账户会话，仍按原有规格服务路径运行。

## 回归验证

macOS 全量验证：

```sh
env DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer bash scripts/validate_macos.sh
```

优先检查 `HomeKitSecurityHardeningTests`、`XiaomiEndpointSecurityTests` 和 `MatterStorageSecurityTests`。
它们使用内存配对、合成协议报文和 URL 策略，不需要扫码、登录或真实设备。
完整脚本还运行原有 Matter 模拟协议测试；不进行 M200 配对。

云端另外用 Swift 6.1 编译实际 HTTP 解析器、内存配对存储和 URL 策略，运行恶意长度、边界输入、
URL 主机校验与撤销测试；对持久化配对 actor 的原代码单独编译并验证并发写入、角色恢复和失败回滚。
这些可移植检查不能替代 macOS Network.framework、URLSession 重定向、钥匙串及 App 的完整编译测试。
